How to contribute

Fork & clone

# fork on GitHub first, then:
git clone https://github.com/YOUR-USERNAME/Bytescript.git
cd Bytescript
git checkout -b my-change

Build it

make          # Windows/MSYS2: mingw32-make
./dist/bytescript --version

Project layout: src/ interpreter (Lexer, Parser, TypeResolving, Compiler, VM, Globals), stdlib_src/ standard library in C, exemples/ sample programs, docs/ + website/ documentation, tests/ test suite.

Make your change — with a test

Language changes should come with a test: drop a NN_name.bs in tests/ plus a NN_name.expected file containing exactly what it should print (trailing tabs from print are ignored).

Run the test suite

make test     # or: ./tests/run_tests.sh
# passed: 24  failed: 0   (plus your new tests!)

Open a pull request

Push your branch and open a PR against main. Describe what you changed and why; CI will build and test your change on Windows, Ubuntu and macOS automatically.

Good first contributions

🐛 Fix a known limitation

The docs list known limitations — making else/elseif work properly is a great, self-contained project. Function-to-function calls are the big one. Shrink it with bytescript -e snippets, fix it, add a regression test.

📚 Documentation & exemples

New programs for exemples/, clearer explanations in docs/ or this website, translations — all valuable, no C required.

🧪 More tests

Exercise a stdlib module (Json, OS, Random…) or a language corner and lock the behaviour in with a test file.

🔌 New C modules

Add a standard-library module in C (HTTP? directories? regex?) following the pattern in stdlib_src/ — see Embedding.

Be kind in issues and reviews — everybody here is learning, including the maintainers. By contributing you agree your work is released under the project's MIT licence.
