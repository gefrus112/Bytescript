Getting started

Bytescript programs are plain text files ending in .bs. A file is a list of statements separated by newlines or semicolons. Comments start with -- and run to the end of the line.

-- hello.bs
print("Hello, World!")

Run it with the interpreter (see the install guide):

bytescript hello.bs

You can also experiment without files:

bytescript -e "print(2 + 3)"   -- run a snippet
bytescript                      -- interactive REPL: type code, see results
Editor tip: the repository ships a VS Code extension with syntax highlighting for .bs files — see editors/vscode/ or the install guide.

Variables & types

Declare a variable with a type and a name. Identifiers start with a letter or _ and may contain letters, digits and _.

Number answer = 42
String name = "Bytescript"
Table scores = { 10, 20, 30 }

answer = answer + 1        -- assignment uses the same name, no type

Built-in types (a type is really a class — yours or a built-in one):

TypeShort formWhat it holds
NumbernumDouble-precision number, up to 15 significant digits. There is no separate boolean type: 0 is falsy, everything else truthy; comparisons return 1/0. The globals true, false and NIL are numbers.
StringstrText, written with double quotes: "hi". Strings are interned constants.
TabletableArray + hash map in one value (see Tables).
Function—Functions are first-class values you can store and pass around.
CData—Opaque data owned by C code (see Embedding).
File—An open file, from the IO built-in.
var—"Any type". Values declared as var skip most type checks.

Prefixing a class name with __ (e.g. __Counter) means "the class itself" rather than an object of it. Declaring a variable without a value (Number x) leaves it holding a garbage value — assign before use.

Operators

KindOperatorsNotes
Arithmetic+ - * / // % **// is floor division, % modulo, ** power.
String..Concatenation: "a" .. "b" → "ab" (calls String:concat).
Comparison== != < > <= >=Return 1 or 0.
Logicand or not, also && || !and/or also exist as value-returning forms via the VM; not x / !x negate truthiness.
Bitwise& | ^AND, OR, XOR on the raw 64-bit value.
Unary-x +x not x !x
Postfixf(args) call · t[i] indexing · obj:method(args) method call · x.field field accessMethod calls with : help the compiler check the signature.

Priority, tightest first: postfix → power → arithmetic → comparison → boolean.

print(2 + 3 * 4)     -- 14
print(10 // 4)       -- 2 (floor division)
print(2 ** 10)       -- 1024
print(-5 + 3)        -- -2
print(not 0)         -- 1

Control flow

If

Number x = 7
if x > 10 then
    print("big")
end
if x <= 10 then
    print("small")
end
Heads-up: else/elseif exist in the grammar but are currently unreliable (see Known limitations). Prefer separate if statements with explicit conditions, as above.

Loops

-- numeric for: start, end (exclusive!), optional step (default 1)
for i = 0, 3 repeat print(i) end        -- 0 1 2
for i = 10, 0, -5 repeat print(i) end   -- 10 5

-- generic for: iterate a table (index, value)
Table t = { 10, 20, 30 }
for i, v in t repeat
    print(v)
end

-- while
Number n = 0
while n < 3 repeat
    n = n + 1
end

-- repeat ... while: body always runs at least once (do-while)
Number m = 0
repeat
    m = m + 1
    if m == 2 then continue end
    if m == 4 then break end
    print(m)
while m < 10 end                       -- prints 1 then 3

break leaves the loop, continue skips to the next iteration.

Functions

func Number fib(Number n)      -- return type, then typed arguments
    if n <= 1 then return n end

    Number a = 0
    Number b = 1
    for i = 1, n repeat
        Number tmp = a + b
        a = b
        b = tmp
    end
    return b
end

print(fib(10))   -- 55
  • The return type and argument types are optional; untyped means var.
  • Functions are values: pass them to other functions.
func Number apply(Function f, Number x)
    return f(x)
end
print(apply(fib, 7))   -- 13
Known limitation: inside a function you cannot call another user-defined function by name (including recursion) — only built-ins/globals, parameters, methods and module functions are visible. Passing functions as arguments, as above, is the way to do higher-order code today.

Tables

A table literal { a, b, c } fills the table's array part (indexes start at 0). Tables also have a hash part for key→value storage.

Table t = { 10, 20, 30 }
print(t:len())          -- 3
print(t[0] + t[2])      -- 40
t:insert(40)            -- append (or use: alloc t -> 40 end)
print(t[3])             -- 40

t:appendHash("name", "bytescript")
print(t:get("name"))    -- bytescript

The alloc statement is sugar for :insert(): alloc t -> 1, 2, 3 end. Full method list in Built-ins → Table.

Classes & objects

class Counter
    -- constructor: a static __new returning the class type.
    -- The compiler creates `self` (the new object) for you.
    func static Counter __new()
        Number self.value = 0     -- declare an object field
        return self
    end

    func increment()              -- normal method: `self` is implicit
        self.value = self.value + 1
    end

    func Number get()
        return self.value
    end
end

Counter c = Counter:new()   -- :new() calls __new
c:increment()
print(c:get())              -- 1
print(c.value)              -- field access with .
  • Defining class Foo … end registers the class object as the global Foo, the object type Foo and the class type __Foo.
  • static methods are called on the class without an object; other methods receive self automatically (call them with :).
  • Fields declared in the class body belong to the class; Type self.field = … inside a method declares an object field (do it in the constructor).
  • Operators on your classes: define dunder methods (__add, __concat, __eq, …) and the compiler routes the operator to them.

Modules & imports

-- import a whole module (file path relative to your program,
-- or a name from the standard library folder)
import "math.dll" as Math end
print(Math:sqrt(16))          -- 4

-- import single names from another Bytescript file
from "exemples/fib.bs" import fib end

-- require: run a file and capture the value it `return`s
require "exemples/speedTests/benchmark.bs" as Function benchmark end
  • import "path" as Name end — the module's top-level names become fields of Name.
  • from "path" import a, b as c end — import selected fields (optionally renamed, types may be given).
  • require "path" as Type name end — like import, but binds the module's returned value.
  • Paths ending in .dll/.so/.dylib load a native C module. Since 1.1 the extension is translated to your platform's, so import "Time.dll" works on Linux/macOS too.
  • Lookup order: current directory first, then the stdlib/ folder next to the interpreter.

Standard library

These ship in the stdlib/ folder next to the interpreter and are imported by file name:

import "math.dll" as Math end
import "Time.dll" as Time end
import "Random.dll" as Random end

Math

Constants Math.pi, Math.e, Math.inf. Functions: max, min, clamp(a,b,c), abs, floor, ceil, round, trunc, sqrt, sin, cos, tan, asin, acos, atan, atanTwo(y,x), exp, log, log10, sign, is_inf, deg, rad — all Number → Number.

print(Math:sqrt(16))     -- 4
print(Math:max(4, 9))    -- 9
print(Math:floor(17/10)) -- 1

OS

env(name), cwd(), chdir(path), absolute(path), normalize(path), filename(path), stem(path), ext(path), parent(path), join(a,b), run(command) → exit code, exit(code).

Time

time() seconds since the epoch · clock() high-precision monotonic seconds (great for benchmarks) · sleep(milliseconds).

Random

seed() · random() in [0,1] · range(min,max) · integer(min,max).

Json

parse(text) → Table · stringify(value) → String · valid(text) → Number · load(path) · write(path, table). Import name is "Json.dll"/"json.dll" depending on platform build — the file is json.*.

Base64 & Debug

import "Base64.dll" as Base64 end
print(Base64:encode("hi"))   -- aGk=
print(Base64:decode("aGk=")) -- hi

Debug:assert(condition, message?) raises AssertionError when the condition is falsy.

Full signatures for every entry: docs/stdlib.md.

Command line

bytescript                 Start the interactive REPL
bytescript <file.bs>       Run a Bytescript program
bytescript -e "<code>"     Run a snippet of code

Options:
  -h, --help               Show help and exit
  -v, --version            Show the version and exit
  -e, --eval "<code>"      Evaluate the given Bytescript code
      --                   Treat the next argument as the file name

In the REPL, blocks (func, if, for…) may span several lines — finish them with end. Errors don't kill the REPL. Commands: .help, .exit.

bs> print(40 + 2)
42
bs> print(undefined_var)

UnknownIdentifierError :
	Unknown identifier : 'undefined_var'

bs> print("still alive")
still alive

Exit codes: 0 success · 1 a Bytescript error was raised · 2 bad command-line usage.

Embedding in C

Your dist/ folder contains the public header and library (bytescript.h, bytev.h, bytescript.lib on Windows / libbytescript.so|.dylib elsewhere). Include the header and link the library; most API functions are CFuncs:

typedef TValue (*CFunc)(TValue* argv, size_t argc);
#include "bytescript.h"
#include <stdio.h>

int main(void) {
    intialize_dependencies();
    initialize_type_specifiers();
    initialize_oop();
    initialize_globals();

    TValue code = make_fstring("print(6 * 7)");
    exec(&code, 1);
    return 0;
}

To write a native module (like the stdlib ones), export two symbols — use BS_EXPORT from platform.h so it works on every OS:

#include "bytescript.h"
#include "platform.h"

BS_EXPORT char* bytescript_module_map = "mymodule_map.bs";
BS_EXPORT TValue bytescript_module_loader(TValue* argv, size_t argc) {
    argv[0] = new_cfunc(my_function);   /* same order as the .bs map */
    return NIL;
}

Compile it as a shared library, drop it in stdlib/ (or next to your script) with its *_map.bs, and import it. Hosts that must not die on script errors can install a jump buffer with bs_set_error_jmp() — errors then longjmp instead of exiting.

Details: docs/embedding.md.

Inside the BVM

Every Bytescript value is a TValue: one 64-bit word using NaN-boxing. If the bits form a normal double it's a Number; quiet-NaN patterns tag the heap types instead:

typedef union {
    uint64_t nan;
    double   num;
} TValue;
  • String — pointer to { len, char str[] }; strings are interned, don't free them.
  • Func — either a C function pointer or compiled bytecode + constant pool.
  • Table — a dynamic array plus a hash table.
  • Class / Object — field arrays (up to 256 fields).
  • CData — opaque pointer for C modules; the VM never inspects it.

Compilation pipeline: lexer → parser (AST) → type resolving → constant folding → class mapping (operators become method calls where needed) → bytecode for a register VM with computed-goto dispatch. Inspect any function with disassemble(f).

Details: docs/bvm.md.

Known limitations

  • No function-to-function calls by name (yet): a function body can only see built-ins/globals, its parameters, methods and module members. Recursion by name doesn't work either — pass functions as arguments instead.
  • else/elseif are unreliable — they can print garbage or nothing. Use separate ifs with explicit conditions.
  • Numeric for end is exclusive: for i = 0, 3 repeat gives 0, 1, 2.
  • Table literals only fill the array part; a literal syntax for the hash part is planned.
  • Variables declared without a value contain garbage until assigned.
  • There is no garbage collector: heap values (tables, objects) are freed manually with free() / :free() when it matters. (Operating systems reclaim everything at exit, so short scripts can ignore this.)
